# AGENTS.md

## What this is
- Client-only React 19 + Vite 8 + TypeScript SPA called **2D Animation Studio**. It previews 1080×1920 (9:16), 24 fps minimalist stickman animations drawn procedurally on a canvas, and exports them at 24, 30, or 60 fps.
- **The house style is minimalist monochrome** (commit `64c14f5`): stark black-and-white UI (zinc palette) and renderers, with at most one vivid accent colour. New work must follow this; older rose/red accent styling was deliberately removed.
- The app has **three sections behind a left sidebar**: **2D Stickman** (`studio`, the canvas animation studio), **Clone Reels** (`reels`, the ranking-countdown reel builder merged in from the old Remotion `ranking-reel-generator` project) and **ViralRank Studio** (`viralrank`, a multitrack shorts/reels editor). Deep links: `?section=reels` / `?section=viralrank` (`?viral=1` also works; `viral`, `shorts`, `editor` and `viralrank-studio` are accepted aliases). The section is written back into the URL and the app listens for popstate, so a pasted link or the back button switches views live.

## Setup and commands
- `npm install` (no lockfile is committed). `npm run dev` serves on port 3000 bound to `0.0.0.0`.
- Verification is `npm run lint`, then `npm run build`.
- `npm run clean` removes `dist` with a cross-platform Node one-liner.
- `DISABLE_HMR=true` is an AI Studio hook that turns off HMR and file watching (see `vite.config.ts`); leave that logic intact.
- Deep links: `?t=4.45` seeds the playhead, `?project=shadow-quit` selects the project, and they combine: `/?project=shadow-quit&t=2`.
- Reel pipeline (Node scripts that run `.ts` directly via type stripping — needs a recent Node, no tsx): `npm run reference`, `npm run visuals`, `npm run voice`, or all three via `npm run reel:build`. They load `.env` with `--env-file-if-exists=.env` and need an `OPENAI_API_KEY` plus FFmpeg/ffprobe on PATH (`SETUP-WINDOWS.md` has the Windows setup; ignore its outdated `tsx` mention). `node scripts/download-clips.ts clips.json [--allow-private]` turns a JSON list of source URLs into `public/reels/blueprint.json` and downloads every clip into `public/source-videos/`.

## Architecture
- `src/App.tsx` owns the app shell: the sidebar section (`studio` | `reels` | `viralrank`), studio state (active tab `player` | `timeline` | `prompts` | `audio`, `StudioConfig`, playhead, play/mute, export modal). `src/components/*` holds the tab views (`PlayerView`, `SceneTimeline`, `PromptHub`, `AudioLab`), the export modal, `ReelStudio.tsx` and `ClipEditor.tsx`.
- `src/types.ts` is the content source of truth: `PROJECTS`, the per-film scene arrays, master prompts, `DEFAULT_CONFIG`, and the monochrome fields `canvasTheme` / `vividAccent` on `StudioConfig`. `SCENES`/`MASTER_PROMPT` are paper-ball aliases for older code.
- **Adding a new film touches at least five places**, and missing one fails silently rather than erroring: `ProjectId` + `PROJECTS` + scenes/prompt in `src/types.ts`; a renderer in `src/animation/`; the renderer dispatch chain in `PlayerView.tsx` (its final `else` draws the shadow-quit world) **and** the separate renderer + `filePrefix` chains in `src/utils/exportVideo.ts`; and a cue list in `src/audio/cueMaps.ts` wired in both `PlayerView.tsx` and `exportVideo.ts` (plus `resetAudioCues` in `PlayerView.tsx`). The preview dispatch and the export dispatch are two independent if/else chains — keep them in sync.
- `src/animation/paperBallRenderer.ts` is the original 10-second Paper Ball Ricochet world; `extendedPaperBallRenderer.ts` the 30s director's cut; `sequelPaperBallRenderer.ts` the Episode 2 sequel (same room and rig, new 8-beat timeline, books / rubber-band launcher); `hoopRenderer.ts` Part 3 (a distant court that grows as he walks, ball-to-face bonks, one slow-motion make, cut to black); `machineRenderer.ts` Episode 4 (hoop falls on him, runaway ball chase, lucky trick shot, net leaves him hanging upside down). `trickShotRenderer.ts` is the 60s trick-shot short: the old hoop snaps on his head and lies broken, the referee wheels a **portable** hoop on at 25.9s, and a burned-in orange narration caption track says what happens to the stickman. `popStageRenderer.ts` is the 58s pop short (Max in purple, Rex in blue, Beep the robot, concert lighting, confetti, burned-in captions). `arcadeClawRenderer.ts` is the 30s neon arcade comedy with a chiptune score (`playArcadeClawScoreSection`), four 7.5s slices, ~45 SFX cues, a trickshot ball timeline (`ballFlight(t)`), a claw timeline (`clawAt(t)`), a giant bear timeline (`giantBear(t)`) and a plush avalanche (`renderAvalanche`). `canvasRenderer.ts` is the Shadow Quit world. Each draws one continuous animation; scene labels are metadata, not render dispatchers.
- Episode 2 opens on Episode 1's aftermath (overturned trash can + five scattered paper balls) and reuses the same world coordinates, so prop positions must stay identical across both 30s films. Part 3 keeps the same character rig and adds a walk, a court and one orange ball.
- `src/components/PlayerView.tsx` owns the `requestAnimationFrame` loop, quantizes preview to 24 fps when `config.fpsMode === 24`, and chooses the renderer from `config.activeProject`. Audio cues fire once via a `Set`; `resetAudioCues(target)` must run on every seek/jump or cues will not replay.
- ViralRank Studio (`src/viralrank/`) is a multitrack editor: `ViralRankStudio.tsx` (UI), `viralRankRenderer.ts` (canvas renderer that draws ranked clips), `audioEngine.ts` (SFX + a browser-voice `speak` fallback), `presets.ts` and `types.ts` (9:16 / 16:9 / 1:1 aspect ratios, effects, transitions). It exports through the shared `ExportModal` with a custom renderer and passes `<video>` elements via `options.videos` → `renderer.setVideos()`. Its preview header has **Safe zones** and **Ranks** switches; **Ranks** flips `showRankingNumbers` (default true) and the renderer hides the whole rank ladder when off. The ladder is anchored to the left-bottom of the safe area: its last row (for a six-rank countdown that is `#6` with its title) sits just above the caption band at `H - 430` and the column grows upward. **Speech was simplified in the monochrome transition**: `src/viralrank/narration.ts` and the `/__reel-tts` endpoint were deleted, so narration (ViralRank and Clone Reels) uses the Web Speech API again — audible in the preview, **not recordable into an export**.
- `src/vite-download-plugin.ts` exposes three dev-only endpoints from the dev server (not part of a production build):
  - `GET /__reel-ping` returns the stamp of the running dev server. `App.tsx` polls it and shows a **reload** banner when the stamp changes, so an open tab that still runs the previous bundle says so instead of quietly behaving like the old code. Every failing reel request is logged to the dev-server console with its status.
  - `POST /__reel-upload` takes the raw bytes plus a URL-encoded `x-file-name` header (a header cannot carry an emoji), probes the file with `ffprobe`, refuses anything that is not a video, re-encodes a codec the browser cannot decode (HEVC and friends become H.264) and returns the public path. **Choose a file** in the editor goes through it. The browser sniffs the first 512 bytes and rejects a saved web page before uploading. Picking the same clip twice is fine: the old copy is removed first because Windows refuses to rename onto an existing file (`EPERM` otherwise). The re-encode is CPU-bound (a 16 s 1080×1920 AV1 clip takes roughly 20 s), so the panel shows a note with the file name and size instead of looking frozen.
  - `GET /__reel-download?url=…` runs the same downloader Node-side (so yt-dlp works), drops the file into `public/source-videos/` and returns the public path. ViralRank Studio uses it from the **Download** button beside each rank's video field (`handleDownloadRankClip` in `src/viralrank/ViralRankStudio.tsx`); once the source is a local `/source-videos/…` path the button disables itself.
- `index.html` carries a small dev-only script that watches for a dead hot-reload socket (the `vite:ws:disconnect` event and the "failed to connect to websocket" console error) and puts an orange **Reload** bar at the top of the page: a dev server restart changes the HMR token and the old tab can never reconnect. It does nothing in a production build.
- File names are sanitised before they are written: `<>:"/\|?*#%` and control characters become `_`. A `#` in a name breaks the public path (Vite answers with the SPA page instead of the file) and a space or an emoji breaks a plain path, so the returned path is percent encoded as well.
- `scripts/lib/downloadSourceVideo.ts` downloads source footage and returns the exact local filepath. A direct MP4 link is streamed with fetch (2 GiB cap, `.part` file cleaned up on failure); a platform URL (YouTube, TikTok, ...) goes through `yt-dlp` and FFmpeg. The output path is resolved from the folder listing as well as from what yt-dlp prints, because the Windows console mangles non-ASCII titles. Redirects are followed manually and every hop is validated; loopback and private-network hosts are refused unless `allowPrivateHosts` is set. The same module lives in the Remotion project at `src/downloader/downloadSourceVideo.ts`; the studio copy is the source of truth.
- Audio is 100% procedural in `src/audio/soundEngine.ts` (Web Audio). Preview speech uses the Web Speech API; export voice uses the Web Audio formant synth. Don't add media files for existing effects.
- `playSynthesizedVoice` is hard-coded to the two Shadow Quit lines. `playSpokenText` is the general formant voice; it is **not** used for reel narration because the result is not intelligible.
- **Long scores must stay scheduled in short sections** — `playPopTrackSection` (58s pop), `playTrickShotScoreSection` (60s epic pop), `playArcadeClawScoreSection` (30s chiptune), `playDiamondHeistScoreSection` (30s sneaky pizzicato), `playPancakeScoreSection` (30s bouncy kitchen comedy), `playVendingScoreSection` (30s bouncy snack-nook comedy), `playBalloonScoreSection` (30s bouncy balloon comedy), `playFindTheBallScoreSection` (30s playful magic-show cup-shuffle score), `playNeedleThreadScoreSection` (30s bouncy sewing-championship score) and the 30s comedy scores `playPingPongScoreSection` / `playDartShotScoreSection` / `playCoinFlipScoreSection` (each four 7.5s slices with silence windows for the gags) all slice their arrangement into chunks. Scheduling a whole track at once creates thousands of live nodes and crashes the tab during a long export.
- Paper Ball cue map (10s film): whoosh **2.0s**, trash rim **4.4s**, lamp **6.0s**, fan **7.5s**, right wall **8.6s**, forehead bonk **9.4s**, desk plop **9.6s**. These times are duplicated in `PlayerView.tsx`, `exportVideo.ts`, `AudioLab.tsx`, and `PromptHub.tsx`; keep all four synchronized when re-timing.
- The other cue maps live in `src/audio/cueMaps.ts` and drive both the preview and the export from one list: `PAPER_BALL_30_CUES`, `PAPER_BALL_SEQUEL_CUES`, `PAPER_BALL_PART3_CUES`, `PAPER_BALL_PART4_CUES`, `POP_STAR_CUES`, `TRICK_SHOT_CUES`, `PING_PONG_CUES`, `COIN_FLIP_CUES`, `DART_SHOT_CUES`, `MIND_TRAPS_CUES`, `ARCADE_CLAW_CUES`, `DIAMOND_HEIST_CUES`, `PANCAKE_FLIP_CUES`, `VENDING_MACHINE_CUES`, `BIGGEST_BALLOON_CUES`, `FIND_THE_BALL_CUES`, `NEEDLE_THREAD_CUES`.
- Export (`src/utils/exportVideo.ts`) is client-side. It renders the requested fps timeline, captures the canvas with explicit frame requests, and mixes the synthesized SFX through a `MediaStreamAudioDestinationNode` into one `MediaRecorder` file. `fixWebmDuration.ts` patches the WebM duration header.
  - **Frame pacing is a fixed capture grid, not a `requestAnimationFrame` loop.** MediaRecorder stamps frames with the wall clock, so a throttled or stalled page freezes the picture while the audio keeps playing. `step()` in `exportVideo.ts` captures at most one frame per `1 / fps` wall-clock slot: rAF drives the foreground on the exact grid, the audio-clock blip pacer keeps a background tab moving, and a 200 ms watchdog covers a stalled audio callback. Keep the capture requests on that grid; no driver may capture twice in one slot.
  - **A suspended AudioContext must never be awaited.** `resume()` stays pending for as long as the browser's autoplay policy blocks it, so awaiting it left the export sitting at 0% with no error at all. The resume is raced against a 1.5 s timeout; if the context still is not running the export continues without an audio track and reports `silent: true` on the result, and the modal says the file has no sound.
  - `ExportOptions` also accepts a custom `renderer`, `duration`, `narration` and `filePrefix`, which is how the Clone Reels and ViralRank workspaces export their own timelines through the same recorder.
  - The modal offers 1/2/3 plays of the project timeline (10s/20s/30s for the 10s film, 30s/60s/90s for the 30s films). Total duration is `(duration × loopCount) / exportSpeed`; the cue `Set` is cleared at each loop boundary so audio repeats with the visuals. Output frames always advance at the selected fps, including slow-motion exports.
  - The modal also offers **24 / 30 / 60 fps** output (`ExportFps` in `exportVideo.ts`). The rate only changes how often the same timeline is sampled — cue timing and total duration stay identical, and the WebM `DefaultDuration` header is patched to match the chosen rate.
  - **WebM/VP9+Opus is the reliable Chromium path.** Chromium reports MP4 support but cannot mux this WebAudio track into MP4; it produces a one-frame file. `canRecordMp4WithAudio()` restricts MP4 to Safari. Don't remove that guard without testing an actual exported file.
  - Exports force safe-zone guides off and ignore the preview fps toggle; the export rate comes from the modal.

## Styling and imports
- Tailwind v4 via `@tailwindcss/vite` and `@import "tailwindcss"` in `src/index.css`; there is intentionally no `tailwind.config.*` or PostCSS config. The studio UI is zinc/black-and-white (monochrome); rose accents are gone.
- `@/*` resolves to the repo root, not `src/` (e.g. `@/src/types`), matching `vite.config.ts` and `tsconfig.json`. Existing code uses relative imports; prefer those.
- `public/` holds the bundled original SVG character art for the Clone Reels (`public/characters/`), sample merge clips (`public/samples/`), downloaded/uploaded footage (`public/source-videos/`), a design reference (`public/assets/aistudio/`) and the generated pipeline output (`public/reels/`, `public/audio/`). Do not add generated video exports to the repo.
- A ranking entry may carry a **video clip** (`RankingVideoClip`): a URL, a manual in/out range, the on-screen length and a manual title. Clips are merged into one countdown in rank order; a title card with the manual title plays before each clip. Cross-origin clips need `crossOrigin` support on the host or the export cannot capture the frame.
- `src/animation/rankingReelRenderer.ts` is the canvas Clone Reels renderer: a centred two-line headline ("Ranking" in white plus the ranking style in the accent colour, then the title), the clip drawn full width and letterboxed on a black frame, and a rank column down the left (#1 at the top, lowest rank at the bottom). A rank is **revealed** once the countdown has reached it: its number turns from grey to the accent colour and its title appears beside it in white, both with a heavy black outline (`outlinedText` strokes first and fills on top). The title card, intro and outro use the same headline and outline language.
  - The Clone Reels preview has the same **9:16 safe areas** toggle as the studio (`Safe areas` in the preview header): dashed bounds, right-hand action bar, bottom caption band; the label sits at the top because the reels headline owns that band. Guides are forced off in every export (`exportVideo.ts` builds `exportConfig` with `showSafeZones: false`).
- The ranking is **dynamic**: clips are entered in play order, the first is `#N` and the last is `#1`, and `normalizeRankingData` renumbers them, so reordering in the editor renumbers the ranks. The rank, the title and the clip always belong to the same entry.
- `src/reels/categoryStyles.ts` holds the eight ranking-style presets (trick-shots, funny-moments, amazing-skills, top-facts, satisfying, animals, gaming, custom). A preset owns the reel background, the accent, the title colour and the title-card timing; clip ranges and titles are separate, so switching style never resets an edit. The Remotion project keeps a copy at `src/ranking/categoryStyles.ts`.
- `src/reels/blueprint.ts` is the shared model for the Node scripts and the app: the blueprint format, the voice presets, the narration rewriter and the loaders for `public/reels/blueprint.json` and `public/reels/reference.json`.
- The reel has a **ranking style** (`RankingVideoData.category`) — the coloured half of the headline; every entry has its own category, which the title card shows. The **Merge videos into the ranking** panel in `ReelStudio.tsx` lists every rank with its clip, title, range and length; **Load a sample merge** fills the top three ranks with the bundled clips in `public/samples/`.
- The **Spoken on / Spoken off** switch in the preview header turns spoken narration off for both the preview and the export path. Since the monochrome transition the voice is the Web Speech API (`speakVoiceOver`) again: it plays in the preview but **cannot be recorded into an export** (that was the whole reason the deleted `/__reel-tts` pipeline existed — don't assume exported reels have voice). The mute button only silences the output; the switch removes the narration lines altogether.
  - The switch also turns the **burned-in caption off**: the editor sets `showCaptions: isNarrationOn` on the render config, and the renderer draws the intro, item and outro captions only when that flag is on. The flag travels into the export through the same config, so a silent reel has no caption plate either. The rank title card is not a caption and always stays.
- `src/reels/videoSources.ts` tells page links (YouTube, TikTok, X, Vimeo) apart from media files, because a page link can never be drawn onto the canvas and captured by the export. A rank can also take a **local file** via **Choose a file**: it is uploaded to the dev server, checked and re-encoded if needed, and lives in `public/source-videos/` from then on, so it previews, trims and exports with the real footage.
- `src/components/ClipEditor.tsx` is the per-rank trimmer: it previews the clip straight from its URL with its own transport, shows the in/out range on a mini timeline, and has **Set start**, **Set end** and **Play in reel** (which jumps the main preview to where that clip plays). It holds its own hidden `<video>` so the source and the merged preview stay independent. It loads with `crossOrigin="anonymous"` first so the frame can be drawn; if the host refuses, it retries without it and reports that the clip can only be previewed, not captured.
